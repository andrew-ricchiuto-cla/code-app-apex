Finish the Apex Simulation as a Dataverse-backed Power Apps Code App without introducing a second local persistence layer. The existing mock fixtures remain available only for local development when the Power Apps runtime is unavailable.

## Architecture

The React app calls the typed Models and Services generated by `pac code add-data-source`. Domain mapper functions isolate generated field names from the existing application types. Hooks use Dataverse in the Power Apps runtime and retain the current fixture data only as an explicit development fallback.

Round lifecycle operations live in a small service layer instead of UI event handlers. That layer receives generated service dependencies, making scoring and lifecycle behavior testable without Dataverse network calls.

## Schema Reconciliation

Keep the existing `mw_` tables and lookups. Add only the metadata needed for stable configuration and current-round selection:

- `mw_round.mw_eventkey` — stable event key used by the weights payload.
- `mw_category.mw_key` — stable category key used by the weights payload.
- `mw_simulation.mw_currentroundid` — lookup to `mw_round`.

Increase the maximum length of event descriptions, contributions JSON, rationale text, and weights payload fields to 4,000 characters where the existing string columns are shorter. Existing status fields remain strings to avoid destructive type replacement.

## Weights and Health Configuration

Weights live in `mw_weightsconfig.mw_payload` as JSON:

```json
{
  "high-attrition": {
    "ai-investment": 0.4,
    "reskilling": 1.4,
    "industries": 0.2,
    "marketing": -0.5,
    "operations": -0.2
  }
}
```

Round event keys and category keys make weights readable and portable instead of binding them to environment-specific GUIDs. The application maps category keys back to allocation category IDs before invoking the scoring engine.

Initial health configuration is centralized in one TypeScript module:

- Baseline: `50`
- Red: `0–39.999`
- Yellow: `40–69.999`
- Green: `70–100`

The Reveal Dashboard displays the average team health as overall system health and applies the same bands to team results. Thresholds and baseline are constants so later adjustment is a one-file change.

## Round Lifecycle

1. **Open Round** changes a pending round to `Open`.
2. Team captains edit allocations and submit only when the exact budget is allocated. Submission timestamps every allocation for that team and round.
3. **Force Advance** timestamps remaining drafts and changes the round to `Locked`.
4. **Reveal Results** is available when all teams submitted or the round is locked. It loads weights and allocations, derives each team's previous health from the most recent revealed round (or baseline), calculates results, upserts one result per team/round, and changes the round to `Revealed`.
5. Re-running Reveal is idempotent and updates existing result rows instead of creating duplicates.

## User Resolution

The Power Apps runtime object ID is matched to `mw_teammember.mw_systemuserid`. Captains and members resolve from the membership record. Facilitator/observer security-role resolution remains a deployment/security task; the existing persona switcher stays visible during build and all routes remain accessible until those roles are configured.

## Error Handling

Generated service failures are surfaced as hook/action errors in the Power Apps runtime. Fixture fallback is allowed only during local development. Admin actions disable controls while running and show a concise failure message without changing the visible round state optimistically.

## Testing

- Mapper tests cover generated lookup/value shapes.
- Health-band tests cover all boundaries and average health.
- Weights tests cover event/category key resolution and default weight behavior.
- Lifecycle tests cover open, force-lock, previous-health selection, scoring, idempotent result writes, and reveal.
- Existing component tests are updated to mock the service boundary rather than Dataverse internals.
- Completion requires the focused tests, full test suite, lint, TypeScript/Vite production build, and a successful Power Apps push verification.
